## 二 · 病根与需求

**速度失配**：7/29 至今画可 30 折、在批 9 折——产折是 AI 速度，读折是人速度。堆一旦超过短期记忆容量，「哪个 block 哪个、哪个已被盖」就只能靠翻。这正是 #60 问的「专读 AI 产出」该长的肌肉，也是中书门下 M2 排序的前置数据（#56-F5 砍掉内置排序后，排序信号本来就该先在数据侧长出来）。

**病根三条**：
- **呈折不声明**——项目归属与关系全埋在标题措辞里（#50 标题里的「取代 #48」就是关系声明，只是机器读不到）；
- **拍板不落面**——会话里批的决定，折面无痕（#58 案）；
- **画可不闭环**——#59 画可时，没人处置被它盖掉的 #58。

需求：
- **R1** 呈折时由 agent 声明项目、种类、关系（依赖 / 覆盖 / 解锁什么）——工具焊入，无人手填表。
- **R2** 待审清单按项目分组，折卡带「等谁」徽章与关系链。
- **R3** 「等谁」四态可见：等你拍 / 等你读 / 等 agent / 闲。
- **R4** 覆盖闭环：画可带 supersedes 声明的折时，被盖折当场处置（close＋判词）；巡检报失配。
- **R5** 存量 9 折立即可用（backfill），不等新折。
- **R6** 数据全长在 GitHub 原生对象上：无新存储、无后端；中书门下 M2/M4 直接消费同一字段。

## 三 · 设计

![数据流：呈折声明 → GitHub 折 → 阅读器/日报/巡检 → 处置闭环](assets/fig-folder-tracking-flow.png)

### 3.1 数据放哪：labels（状态）＋ 尾行标记（关系），双轨

**labels——可变状态，GitHub 原生可筛、自带颜色**：

| 前缀 | 取值 | 说明 |
|---|---|---|
| `proj:` | zhongshumenxia / menxia / niw / guanzhi / … | 开放集；agent 起新词前先查现有 labels；词表登记进门下 wiki |
| `kind:` | 拍板 / 评审 / 设计 / 读物 / 交付 / 参考 | 主用途取一 |
| `wait:` | 你拍（红）/ 你读（黄）/ agent（蓝）/ 闲（灰） | 阅读器直接用 label 颜色，零映射表 |

**body 尾行标记——一次性声明的关系边**（与 `happy-session` 同族，读者不可见）：

    <!-- menxia-rel: needs=#49; supersedes=#48,#50; unblocks=T1.2 租机链 -->

- `needs=#N`：本折依赖 #N 的结论；
- `supersedes=#N`：本折覆盖/取代 #N；
- `unblocks=<短语>`：画可后解锁什么（自由文本，禁分号）；
- 多项目折允许多个 `proj:` label，阅读器按第一个分组。

**单点定义**：词表常量只在 menxia-mcp 一处定义；阅读器只认前缀（`proj:` / `kind:` / `wait:`），不硬编码取值全集——改名的教训：跨系统契约是裸字符串，两头写死必静默失效。

**为什么不是别的**：
- **GitHub Projects / milestone**：第二块阅读面，违背 attention-hub 初衷；Projects 写入要 GraphQL、移动端弱；milestone 单亲装不下多项目。
- **本地状态文件**（processed.json 那类）：阅读器跑在浏览器里，看不见 Mac 上的文件；关系必须公开长在折上。
- **AI 语义自动判覆盖**：误报要人擦屁股。声明优先；语义扫描只做定期巡检的兜底（§3.4），不进机制。

### 3.2 写入侧（menxia-mcp）

`open_folder` 增 `track` 参数：`{ proj, kind, needs?, supersedes?, unblocks? }` → 贴 labels（幂等，缺则按定色新建）＋ 焊尾行标记。不传 `track` 出 warning，不硬拦（与 body 缺段同级）。

**溯改老折只 close 不改 body**：给存量折补关系一律「close ＋ 判词 comment」，不碰老折 body——别惊动 `happy-session` 标记。

### 3.3 阅读侧（menxia）

`listOpenPRs()` 的响应里 **labels 和 body 本来就有**（现在扔掉没用）——分组、徽章、关系链**零新增 API 请求**。sidebar 按 `proj:` 分组、`wait:` 定色、`kind:` 作徽章；尾行标记解析复用 `parseHappySession` 同族正则，关系 chips 点击跳折。落地排在 `integrate/five-branches` 合完之后（那五条分支在飞，别撞）。

### 3.4 闭环（audit_folders 增三类巡检，只报不动手）

1. 已画可折声明 `supersedes=#N` 而 #N 还 open → **僵尸候选**；
2. open 折 `needs=#N` 而 #N 已画可 → **已解锁，可动手**；
3. `wait:你拍/你读` 但 needsReply>0 → **漂移**（其实在等 agent）。

处置权在你：巡检只报候选，close 永远等你一句话。

### 3.5 doorbell / 8-8 结账对接

doorbell 日报从「14 折待决」升级为**分项目计数＋等你拍 Top3**。你已批过「结论页行动率拆开算」——`proj:` label 就是「拆开算」的实现前提；存量僵尸清掉，行动率的分母立即变干净。

### 3.6 与中书门下的关系

这就是中书门下「收进来的东西自带项目/状态维度」那一块，前置到门下现有面上。字段长在 GitHub 对象上：M2 排序直接拿 labels 当特征，M4 门下并入时零迁移。与 #56-F5（M1–M2 砍内置排序）同向：排序**模块**可以砍，排序**数据**从今天就开始攒。
